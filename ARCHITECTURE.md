# EduJob — технический документ (v0.3)

Двусторонний job-маркетплейс, специализированный под сферу образования:
учреждения (школы, детсады, колледжи, вузы) ищут и подбирают специалистов
(учителя, преподаватели, методисты, психологи, административный/
хозяйственный персонал). По сути — узкая вертикаль JoopBar-подобной
модели, а не мультивертикальная платформа. Соло-разработка с Claude Code.

## 1. Домен

Одно ядро, один поток:

Institution (школа/сад/колледж/вуз) → StaffRequest (вакансия) →
Candidate (специалист в сфере образования) → Application → ИИ-скрининг →
найм.

Сущности: Institution (тип, регион, верификация), роли внутри учреждения
(director / HR / staff — с разными правами на публикацию и работу с
вакансиями с самого старта), Candidate (профиль, резюме,
специализация/предмет, квалификация/категория, уровень образования, с
которым может работать — дошкольное/школьное/СПО/высшее), подписка/
биллинг на уровне учреждения.

Отраслевая специфика, которой нет у общего джоб-борда и которую стоит
заложить в модель данных с самого начала:
- квалификационная категория/аттестация педагога
- предмет/дисциплина и уровень образования (дошкольное/начальное/среднее/СПО/вуз)
- требования по документам (диплом, справки, при необходимости —
  судимость/мед.книжка) как часть верификации кандидата
- сезонность спроса (набор кадров к началу учебного года)

## 2. Стек

- Backend: Laravel 12 (монолит, все секреты и процессы в одном месте)
- Очереди: Redis + Horizon — все ИИ-вызовы асинхронно, никогда синхронно в HTTP
- Публичная часть: Inertia + Vue 3 + Tailwind
- Админка/бэк-офис: Filament
- БД: PostgreSQL, своя (не BaaS), RLS — по необходимости для изоляции учреждений
- ИИ: Anthropic API напрямую с бэкенда, через джобы
- Auth: телефон + SMS-код, кастомный guard в Laravel (без email-костылей)
- Биллинг: `PaymentGatewayInterface` с первого дня; первый драйвер — ручной инвойс, следующий — мбанк/Элсом
- Деплой: Docker Compose на своём VPS/DigitalOcean — один деплой, без сплита фронт/BaaS

## 3. Принципиальные решения (зафиксировать, чтобы не расползлось)

1. Никакого разделения хостинга бэкенда и хранения секретов между разными
   платформами (это была корневая причина проблем в прошлом похожем проекте).
2. Все ИИ-операции — через очередь, с ретраями и таймаутами, не в теле запроса.
3. Многотенантность на уровне Institution с первого дня, даже в MVP.
4. Биллинг — за интерфейсом, чтобы провайдера можно было сменить без переписывания домена.
5. Отраслевые поля (предмет, категория, уровень образования, документы)
   — часть ядра модели кандидата с первой миграции, не надстройка поверх
   generic-резюме.

## 4. Killer-фичи под рынок КР (согласовано)

Приоритетные, закладываем в модель данных и роадмап с самого начала:

- **Telegram как второй полноценный канал**, не единственный: бот дублирует
  вакансии/отклики/уведомления параллельно с сайтом (не вместо), т.к. HR
  учреждений в Бишкеке ожидают полноценный веб-интерфейс, а массовый
  кандидат в регионах — Telegram.
- **Пакетный набор ("массовый режим")** — отдельная сущность/флоу для
  района/области: публикация сразу N вакансий на район с агрегированной
  статистикой дефицита по предметам.
- **Ранняя публикация вакансий на следующий учебный год**: учреждение
  может опубликовать вакансию заранее (весна/лето) с пометкой "на
  следующий учебный год"; кандидат может заранее откликнуться/оставить
  интерес — закрывает сезонный пик перед 1 сентября.
- **Верификация через официальные реестры** категорий/аттестации педагогов
  и учреждений (на старте — модератором вручную, позже — интеграция).
- **Региональный дисбаланс как фича**: явное поле "готов к переезду" +
  условия (жильё, подъёмные, доплата за удалённость) у кандидата, и
  соответствующие поля у вакансии.
- **Двуязычные ИИ-резюме** (кыргызский + русский) — генерируются
  одновременно как обязательная часть флоу, не отдельная опция.
- **Совместительство/частичная занятость как первоклассный сценарий**:
  фильтр "готов на 0.5 ставки/совместительство" у кандидата, у вакансии —
  поле объёма ставки; поддержка нескольких активных откликов кандидата в
  разных учреждениях одновременно.

## 5. Принятые решения (закрытые вопросы)

- **Верификация учреждений**: вручную модератором на старте (без интеграции с реестром Минобра).
- **Верификация кандидатов**: обязательны диплом об образовании и категория/аттестация педагога; судимость/мед.книжка — не в MVP.
- **Регион**: только Кыргызстан.
- **Монетизация**: подписка учреждения (тарифы), кандидаты — бесплатно.
- **Роли учреждения**: сразу director / HR / staff с разными правами, не единая роль.
- **Сезонность**: ранняя публикация вакансий на следующий учебный год как отдельный флоу.
